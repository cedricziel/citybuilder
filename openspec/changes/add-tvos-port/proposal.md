## Why

Citybuilder ships on iPhone, iPad and Mac. The App Store Connect record and the fastlane match profiles already cover tvOS, but there is no Apple TV app. The game does not run there because its input assumes a finger or a pointer: map pan and zoom use `DragGesture` and `MagnificationGesture`, the scene reads touch locations, and the HUD uses `Stepper`, `Slider` and `keyboardShortcut`, none of which tvOS offers. Apple TV also has no persistent local storage, so the Application Support save folder does not survive. Now that iOS and Mac release through TestFlight, Apple TV is the remaining platform in the Universal Purchase.

## What Changes

- New `CitybuilderTV` app target in `project.yml` (tvOS 18, bundle id `com.cedricziel.citybuilder`, shared with the other targets for Universal Purchase). Every local package adds `.tvOS(.v18)` to its platforms. CityCore code does not change.
- **Remote-driven map.** A reticle marks the tile under the screen center (`Camera.centerTile()`). It replaces the touch point and the hover pointer. Swiping on the Siri Remote pans the camera. Directional clicks step it one tile. Clicking selects the reticle tile. Press-and-hold opens the tile context menu that iOS opens on long-press. Play/Pause toggles the simulation. A standard game controller works too: left stick pans, triggers zoom, A selects, B goes back.
- **Zoom.** Zoom has HUD buttons on tvOS, plus the controller triggers. The remote has no pinch.
- **Placement on tvOS** reuses the pending-placement flow from `add-touch-first-placement`. The pending anchor follows the reticle, select confirms, Back cancels. With a road or demolish tool armed, select toggles painting on and off, and while painting is on each tile the reticle crosses gets the tool applied.
- **Focus-driven HUD.** Swiping down from the map into the HUD moves focus into the build rail and menu buttons, and Back returns focus to the map. A new TV HUD layout uses tvOS safe-area margins and larger type for viewing at a distance.
- **Controls tvOS lacks:** `Stepper` (manifest editor) and `Slider` (audio settings) become −/+ button pairs on tvOS. `keyboardShortcut` and Handoff (`NSUserActivity` advertising) are compiled out.
- **Saves on tvOS** go through CloudKit, using the record format from `icloud-sync`. This adds the first production CloudKit client, plus a call that lists a user's saved games. The local copy lives in Caches. With no iCloud account, the game still plays, but the title screen warns that progress is not kept.
- **Audio:** the `.playback` / `.mixWithOthers` session and interruption handling also apply on tvOS.
- **Layered tvOS app icon and Top Shelf image**, generated by extending `scripts/generate-app-icon.swift`.
- **CI and release:** a `build (CitybuilderTV)` job is added to `ci.yml` and the `ci-ok` gate. A `tv` target is added to the Fastfile and a `tvos` entry to the TestFlight matrix in `release-please.yml`. Testing stays internal only.

## Capabilities

### New Capabilities

- `tv-remote-controls`: how the Siri Remote and game controllers drive the map, the reticle, selection, placement, painting and HUD focus on Apple TV.

### Modified Capabilities

- `platform-shells`: Universal platform support adds Apple TV. Adaptive HUD gains a TV layout. Audio session and interruption requirements cover tvOS. Settings audio controls allow a stepped control where `Slider` is unavailable. Handoff is excluded on tvOS.
- `rendering-2_5d`: Input mapping adds remote and controller inputs. The iOS arrow-button Placement HUD stays iOS-only; tvOS placement is specified in `tv-remote-controls`.
- `persistence-save-load`: Save location gains a tvOS path (Caches, mirrored to CloudKit).
- `icloud-sync`: on tvOS, sync is the only durable store, and a missing iCloud account warns that saves are not kept.

## Impact

- **project.yml / Apps/**: new `CitybuilderTV` target, `Apps/CitybuilderTV/` (app entry, Info.plist, entitlements, layered icon asset catalog) and scheme.
- **Packages/\*/Package.swift**: `.tvOS(.v18)` platform on all six packages. CityCore stays framework-free and unchanged, and `scripts/check-no-apple-ui-imports.sh` still gates it.
- **CityUI**: remote input mapping as a platform-neutral view-model (tested on the macOS host), TV HUD layout, focus sections, −/+ steppers, `#if os(tvOS)` wiring of `onMoveCommand`, `onPlayPauseCommand`, `onExitCommand` and GameController.
- **CityRender2D**: touch-location handling in `IsoWorldScene` is narrowed from `canImport(UIKit)` to `os(iOS)`, so the remote's relative touches never become tile taps.
- **CityAudio**: `os(iOS)` session guards widen to `os(iOS) || os(tvOS)`. Audio sliders get a tvOS stepped variant.
- **CityPersistence**: platform default for the save directory. A production `CKContainer`-backed `CloudKitClient` and a `listGames()` call, wired into the tvOS save path only. Save format unchanged. The CloudKit schema must be deployed to the production environment before tvOS TestFlight builds can sync.
- **CI / release**: `ci.yml` build matrix and `ci-ok`, `fastlane/Fastfile` targets, the `release-please.yml` TestFlight matrix. The match tvOS profile and the ASC tvOS platform already exist.
- **Determinism**: no simulation change. Remote input becomes the same `Command`s at tick boundaries.
- **Tooling**: no new build-time tool dependency. GameController is an Apple system framework.
